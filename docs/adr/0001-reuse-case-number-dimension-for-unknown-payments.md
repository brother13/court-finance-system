# 复用案号维度表达不明款辅助案号

不明款科目需要进入现有辅助核算余额表，但系统当前以 `case_no` 作为该报表的统一分组维度。决定不新增账套开关或新的不明款辅助维度，而是由科目是否挂载 `case_no` 自然启用：普通案款科目继续使用真实案号，不明款科目则使用“非空的缴款人＋非空的银行备注＋持久化 BMK 编号”作为不明款辅助案号。未挂载该辅助核算的客户保持原业务不变；不明款认领仍属于缴费登记范围，不纳入本次不明款凭证生成设计。

## Considered Options

- 新增独立的“不明款标识”辅助维度，并扩展辅助余额表支持任意维度。
- 增加账套级开关控制不明款辅助核算。
- 复用现有 `case_no`，由科目辅助配置决定是否启用。

## Consequences

- `case_no` 在不明款科目上不再必然表示法院真实案号，界面和后续查询不得无条件把它用于案件统计。
- 不明款辅助案号整体作为普通 `case_no` 辅助值，辅助余额表沿用现有汇总逻辑，不增加不明款专属计算分支。
- 缴款人或银行备注为空时省略对应文本段，不使用银行摘要补位；BMK 编号始终保留，因此辅助值不会为空。
- 所有新导入的不明款都持久保存账套内唯一的 `aux_case_code`，不按科目辅助配置分支。导入落库时生成 `BMK-XXXXXXXX`，发生短码冲突就重试；删除凭证并重新制证时复用原编号，不重新生成。科目是否挂载 `case_no` 只决定制证时是否使用该编号。
- 不明款原始导入数据不提供修改流程，辅助案号一经形成即保持不变。辅助值总长度限制为 200 个字符，BMK 编号不得截断；超长时先截断银行备注，再截断缴款人。
- 只有实际挂载 `case_no` 的科目分录才写入不明款辅助案号；借方到账科目未挂载时不得写入。科目一旦挂载辅助核算，对应辅助值即为必填。
- 不新增历史迁移标记或自动回填脚本。操作人员负责删除原不明款业务凭证，使来源记录恢复为未制证，再在科目挂载辅助核算后重新制证；存量期初辅助明细由操作人员录入并自行核对总账与辅助账平衡。
- 历史调整必须遵守顺序：先清除阻止科目配置的有效凭证和原非零期初，再挂载辅助核算，然后录入总账及辅助期初并重新生成业务凭证。
- 手工录入的不明款辅助期初属于启用前余额，辅助案号由操作人员自行编制并保证不重复，不回写 `fin_case_fund_unknown_payment`，也不要求与启用后的业务记录逐笔关联。
- 所有新导入的不明款均由系统生成并持久保存 BMK 编号；已删除的业务凭证重新生成时复用来源记录上的编号。手工期初编号与系统生成编号只需在同一辅助账中保持不重复。
- 系统分配新 BMK 编号时，除检查不明款业务记录外，还必须把现有辅助期初和凭证辅助值中的 BMK 编号视为已占用；发生冲突时重新分配。
