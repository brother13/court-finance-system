# PHP 与 ThinkPHP 升级前评审

日期：2026-10-22。状态：访谈中，尚未执行升级。

## 已确认决策

- 直接升级 PHP 8.5 已修复稳定版本并升级 ThinkPHP，MySQL 暂不升级。参见 ADR 0002。
- 历史问题单独登记；金额、凭证或数据安全关键问题阻止上线。
- 切换维护窗口预留两小时，由演练验证切换和恢复能否在窗口内完成。
- 用户负责业务验收。

## 决策树

1. 升级边界：方向已确认。
   - 目标框架和锁定依赖：ThinkPHP 8.1.4 有官方 PHP 8.5 兼容声明，可作为候选；ThinkORM 主版本和整套依赖须锁定，项目验证待完成。
   - 现有服务漏洞处置：部署事实与临时处置方案待确定，不能等待框架迁移结束才处理风险。
2. 切换边界：两小时窗口已确认。
   - 停止新增请求和后台写入、处置在途任务、备份及恢复演练：方案待确认。
   - 切换后何时开放写入：待确认。
   - 超时或验收失败后的安全退路：待确认；未经修复的旧 PHP 不能直接恢复对外服务。
3. 验收边界：用户验收，关键问题阻止上线，已确认。
   - 测试样本、完整账务对比、代表性导入与打印、耗时基线：准备中。
   - 恢复旧备份不得覆盖切换后已产生的新凭证等账务记录。
4. 交付范围与恢复策略：本机验证及部署包，还是本轮包含正式服务器切换，尚待用户确定；无法在两小时内安全恢复时的业务安排待确定。

## 本轮核实的事实

- 通过直接 PDO 只读查询核实：当前本地配置所连 MySQL 为 5.7.44，启用 ONLY_FULL_GROUP_BY、STRICT_TRANS_TABLES 等严格模式。项目文档中的 8.0 描述与此不符；本地结果不代表正式服务器。
- ThinkPHP 官方 8.1.4 发布说明明确兼容 PHP 8.5。当前框架为 backend/thinkphp 独立源码，backend/composer.json 只管理 PDF 依赖，不能通过一次 composer update 完成迁移。官方所述无缝升级范围不覆盖本项目 TP5。
- Web、finance_job_worker.php、detail_ledger_pdf_job.php 均显式加载旧框架。任务启动器会自动寻找 CLI PHP，未验证 PHP 版本，须防止升级后 Web 与后台使用不同版本。
- FinanceAsyncJobWorker.php 的异常处理依赖旧框架事务计数、循环回滚和连接清理。必须验证“凭证已提交但任务未成功”“部分失败后重试”“旧进程与新进程抢占”场景，防止重复制证或状态失真。
- 本地有效财务任务只读快照：SUCCEEDED 91、FAILED 15、PARTIAL_FAILED 2，未见 QUEUED/RUNNING。此快照仅说明本地取证时状态，正式切换前须重新核实目标环境，不能整批重跑失败任务。
- 导入任务保存 runtime/finance_async_jobs/imports 下文件路径及摘要；PDF 任务另有 runtime 状态文件。不能把整个 runtime 一概视为可丢弃缓存。
- 对 backend/app、backend/public、backend/scripts 的当前源码搜索未发现 CREATE TABLE、ALTER TABLE 或 ensureSchema 自动补丁路径。新单位初始化手册明确不允许在已有业务数据后重跑初始化脚本。
- 普通 API 分发会写请求日志；“只读核验”指不改变账务及业务状态，不能宣称普通 API 调用绝无任何数据库写入。

## 财务专业业务规则

- 升级保持借贷平衡、整数分金额运算、账套与期间隔离、辅助核算必填、凭证编号和审计约束。
- 新旧一致只是验证条件之一；两边一致但同时违反财务规则仍不得验收。
- 严格校验金额边界、数字字符串标识符、空值、日期和期间。既有金额精度回归应纳入迁移检查。
- 测试写入使用隔离数据副本；不得让新旧服务或不同版本的任务进程同时处理正式业务。

## 数据库结构与运行配置

- 本次不预设新增或重建业务表，不清空、不重算历史账务；若兼容性确实要求结构变更，应另行提出具体迁移设计。
- 分别核实本机、测试和正式环境的 MySQL 版本、SQL mode、字符集、排序规则、时区、事务隔离及驱动配置，不直接采用文档中的默认环境描述。
- 检查所有启动和部署脚本，避免升级时意外执行初始化、预置数据或数据库补丁。
- 完整备份范围须覆盖数据库、必要上传文件和附件、配置、代码与锁定依赖；备份有效性以隔离环境恢复成功为准。

## 业务流转与发布流程草案

核实环境及漏洞处置 → 隔离环境迁移 → 技术回归与用户业务验收 → 恢复/切换演练 → 维护窗口停止所有业务写入 → 确认在途事务及任务状态 → 最终备份 → 切换所有 PHP 执行入口 → 只读核验 → 确认后开放业务写入。

这是一份待确认流程，不能据此直接操作正式环境；开放写入后的故障处理不得简单覆盖恢复旧备份。

## 接口范围
