# 已对账业务数据删除与重新对账

## 1. 财务业务规则

- 已对账业务记录仍关联有效凭证时，必须先通过凭证中心删除凭证，再删除业务数据；凭证删除继续执行原有权限、状态和期间限制。
- 未生成凭证，或原凭证已经删除的业务记录，允许直接删除。银行对账结果不再单独构成删除障碍。
- 删除业务数据时，相关对账结果必须同步失效，保留原银行流水，恢复为未对账，之后由用户重新执行对账。
- 同一银行流水存在多个候选结果时，该流水全部旧候选一并失效，避免保留已过期的重复或金额差异结论；不删除其他候选业务数据。
- 保留现有退汇确认关联保护、账套和年度隔离、删除权限及审计要求。银行流水自身的删除限制不变。

## 2. 数据库表、字段与关联

复用现有业务表、`fin_case_fund_bank_reconcile`、`fin_case_fund_bank_statement` 和 `sys_audit_log`，不新增表、字段、索引或迁移。

- 通过 `account_set_id + fiscal_year + biz_type + biz_id + del_flag=0` 查找当前业务的有效对账结果。
- 从结果取得关联 `statement_id`，在当前账套、年度内锁定银行流水及该流水全部有效结果。
- 旧结果使用 `del_flag=1`，维护更新人和更新时间；银行流水 `reconcile_status` 恢复 `UNMATCHED`。
- 业务数据沿用原有删除方式；审计记录保留删除前业务快照、失效对账结果和银行流水原状态。

## 3. 业务流转

开始事务 → 锁定账套（与自动对账共用锁）→ 锁定并校验选中业务 → 校验有效凭证和退汇关联 → 失效相关对账结果、恢复银行流水未对账 → 删除业务数据 → 写入审计 → 提交。

任何校验或写入失败均回滚；批量请求任一条不满足条件则整批不删除。没有关联流水的业务单边项仅失效自身结果。

## 4. 后端接口

复用 `/caseFund/refundDelete`，以及使用同一删除服务的 `/caseFund/paymentDelete`、`/caseFund/unknownPaymentDelete`、`/caseFund/distributionDelete`。参数、`deleted_count` 响应和 `case_fund:delete` 权限不变，无需手工撤销对账接口。

## 5. 枚举、字典与档案

继续使用 `UNGENERATED`、`GENERATED` 制证状态、既有对账结果状态和银行流水 `UNMATCHED` 状态。不新增枚举或辅助核算档案。

## 6. 实现与验证

- 业务删除校验只保留凭证等业务约束，移除“存在对账结果即禁止删除”。
- 银行持久化服务负责相关结果失效和流水恢复，外层删除事务负责原子性及审计。
- 前端删除确认提示与后端规则一致，不仅凭冗余制证状态拒绝请求。
- 回归覆盖已对账未制证、原凭证已删除、有效凭证阻断、业务单边项、多候选、数据隔离及失败回滚。执行相关后端测试、前端测试和构建。
